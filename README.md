# IT Resume Retention Analysis

Анализ удержания пользователей образовательной IT-платформы IT Resume и исследование раннего поведения пользователей, связанного с последующим возвращением на платформу.

Проект выполнен в рамках магистерской программы МИФИ + Simulative «Анализ и инженеринг данных».

## О проекте

IT Resume работает по подписочной модели, поэтому для платформы важно не только привлекать новых пользователей, но и удерживать их после регистрации.

Цель проекта — изучить retention пользователей, определить, на каком этапе происходит основной отток, и выяснить, какие особенности поведения в первые дни связаны с дальнейшим возвращением на платформу.

В рамках исследования:

- рассчитаны N-day и Rolling retention;
- проведён когортный анализ;
- изучено поведение пользователей в первые дни после регистрации;
- проверены восемь продуктовых гипотез;
- проведена статистическая проверка обнаруженных различий;
- сформулированы продуктовые рекомендации;
- подготовлены SQL-запросы для дашборда в Metabase.

## Данные

Анализ основан на данных платформы IT Resume.

В исследовании используются данные о:

- регистрациях и входах пользователей;
- работе с задачами: CodeRun и CodeSubmit;
- успешных и неуспешных решениях;
- сложности задач;
- прохождении тестов;
- операциях с внутренней валютой CodeCoins.

Технические пользователи с `id <= 94` исключены из анализа.

Период регистрации анализируемых пользователей: с ноября 2021 года по апрель 2022 года.

## Основные результаты

Наиболее заметное снижение активности пользователей происходит в первые дни после регистрации:

- D1 retention — **15.66%**;
- D7 retention — **4.38%**;
- D30 retention — **1.04%**.

Rolling retention заметно выше N-day retention: Rolling D7 составляет **22.26%**, Rolling D30 — **13.02%**. Это показывает, что часть пользователей возвращается на платформу нерегулярно и может пропускать конкретные контрольные дни.

Наиболее выраженная связь с D7 retention среди рассмотренных категориальных признаков обнаружена для регулярности активности в первые три дня. D7 retention увеличивается с **0.72%** среди пользователей без активности в D0–D2 до **31.11%** среди пользователей, активных во все три дня.

Более высокий D7 retention также наблюдается среди пользователей, которые в D0–D2:

- начинают работать с задачами: CodeRun — **11.14% против 1.92%**;
- отправляют решения: CodeSubmit — **10.94% против 2.06%**;
- получают успешное решение — **13.04% против 2.03%**.

При этом анализ не подтвердил предположения о том, что первый успешный результат обязательно должен быть получен максимально быстро или на более простой задаче.

Раннее использование CodeCoins также связано с более высоким D7 retention, однако обнаруженная связь невелика.

Полученные результаты показывают статистические связи между поведением пользователей и retention и не позволяют сами по себе сделать вывод о причинном влиянии этих факторов.

## Продуктовые рекомендации

По результатам анализа определены четыре направления для дальнейшего тестирования:

1. Стимулировать повторное взаимодействие пользователя с платформой в первые дни после регистрации.
2. Сократить путь от регистрации до начала работы с первой задачей.
3. Помочь пользователю получить первый успешный результат без искусственного упрощения первой задачи.
4. Дополнительно проверить роль CodeCoins в раннем вовлечении пользователей.

Предложенные изменения требуют проверки с помощью продуктовых экспериментов.

## Дашборд

В Metabase подготовлен интерактивный дашборд для анализа регистрации, активности и удержания пользователей.

Дашборд включает:

- основные KPI: количество пользователей, D7, D30 и Rolling D30 retention;
- динамику регистраций;
- N-day и Rolling retention;
- когортную матрицу;
- распределение пользовательской активности;
- сравнение retention в зависимости от ранних действий пользователей;
- анализ использования CodeCoins.

Для анализа отдельных срезов используются фильтры по периоду регистрации, количеству активных дней в D0–D2, типу ранней активности и сложности первой задачи.

## Ограничения

- `userentry` содержит только первый зафиксированный вход пользователя за день, поэтому данные не позволяют оценить количество сессий внутри дня.
- Часть зарегистрированных пользователей не имеет записей в `userentry`.
- В `userentry` присутствуют идентификаторы, отсутствующие в `users`; такие записи исключены из расчётов.
- Для более поздних когорт доступен меньший период наблюдения, поэтому долгосрочный retention можно рассчитать не для всех когорт.
- Rolling retention зависит от доступного периода последующего наблюдения и используется как дополнительная описательная метрика.
- Результаты анализа показывают статистические связи, но не доказывают причинное влияние исследованных факторов на retention.
